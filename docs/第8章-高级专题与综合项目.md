## 第 37 课：代码生成器

### 37.1 学习目标

- 理解代码生成器的完整流程：**导入表 → 编辑生成配置 → 预览 → 生成代码**。
- 理解基本信息与生成信息两类表单的作用。
- 理解字段配置中"列表、查询、必填、显示类型、查询方式、字典"等选项如何影响生成结果。
- 能把生成的文件对应到 `src/views`、`src/api` 的目录结构。

### 37.2 课前准备

- 打开 `src/views/tool/gen/index.vue`，`src/views/tool/gen/editTable.vue`，`basicInfoForm.vue`，`genInfoForm.vue`。
- 打开 `src/api/tool/gen.js`，阅读接口列表。

### 37.3 知识讲解

#### （一）流程总览

```
数据库中已有的表
   │ ① 导入表（importTable.vue → POST /tool/gen/importTable）
   ▼
代码生成表记录（sys_gen_table / sys_gen_table_column，由后端保存）
   │ ② 编辑配置（editTable.vue → GET /tool/gen/{id}，PUT /tool/gen）
   │ ③ 预览（handlePreview → GET /tool/gen/preview/{id}）
   ▼
④ 生成代码（GET /tool/gen/genCode/{tableName}，或批量 /tool/gen/batchGenCode 打包 zip）
```

列表页的按钮与接口一一对应：

| 按钮 | 调用 | 接口 |
| --- | --- | --- |
| 导入 | `openImportTable` | `POST /tool/gen/importTable` |
| 预览 | `handlePreview(row)` | `GET /tool/gen/preview/{tableId}` |
| 编辑 | `handleEditTable(row)` | 打开 `/tool/gen-edit/index/{tableId}` 页签 |
| 同步 | `handleSynchDb(row)` | `GET /tool/gen/synchDb/{tableName}` |
| 生成代码 | `handleGenTable(row)` | `GET /tool/gen/genCode/{tableName}` 或 zip 下载 |
| 删除 | `handleDelete(row)` | `DELETE /tool/gen/{tableId}` |

> 注意：所有按钮都带有 `v-hasPermi`（如 `tool:gen:code`、`tool:gen:import`），代码生成是高权限功能。

#### （二）生成方式：下载 zip 与自定义路径

`handleGenTable` 中有一个分支：

```js
if (row.genType === "1") {
  genCode(row.tableName)       // 生成到自定义路径（genPath）
  // 提示："成功生成到自定义路径：" + row.genPath
} else {
  // 默认：打包下载 zip（批量时使用 batchGenCode）
  proxy.$download.zip("/tool/gen/batchGenCode?tables=" + tbNames, zipName)
}
```

- `genType` 为 `0`（默认）：后端打包为 zip，浏览器下载，开发者手动复制到项目；
- `genType` 为 `1`：直接写入后端配置的 `genPath` 目录。

#### （三）基本信息与生成信息

**基本信息**（`basicInfoForm.vue`）：来自数据库表本身的信息，包括：

| 字段 | 含义 |
| --- | --- |
| 表名称 `tableName` | 数据库中的表名 |
| 表描述 `tableComment` | 生成代码的注释与菜单名来源 |
| 实体类名称 `className` | 后端 Java 实体类名（如 `SysUser`） |
| 作者 `functionAuthor` | 代码头部注释 |
| 备注 `remark` | 说明 |

**生成信息**（`genInfoForm.vue`）：决定代码"长什么样"，包括：

| 字段 | 可选值 / 含义 |
| --- | --- |
| 模板类别 `tplCategory` | `crud` 单表增删改查、`tree` 树表、`sub` 主子表 |
| 前端模板 `tplWebType` | `element-ui`（Vue2）、`element-plus`（Vue3）、`element-plus-typescript` |
| 包名 `packageName`、模块名 `moduleName`、业务名 `businessName`、功能名 `functionName` | 决定后端包路径、前端 `views` 子目录、接口路径等 |
| 表单布局列数 `formColNum` | 表单每行的列数 |

> 命名对应关系（以 RuoYi 约定为准）：`moduleName` 与 `businessName` 通常决定 `src/views/{moduleName}/{businessName}/index.vue` 与 `src/api/{moduleName}/{businessName}.js` 的位置。这一点可在生成的代码中通过 `import` 路径核对。

#### （四）字段配置：决定页面长什么样

`editTable.vue` 中"字段信息"页签的每一列，都直接影响生成的页面：

| 配置列 | 作用 | 示例 |
| --- | --- | --- |
| 列表 `isList` | 是否出现在列表表格中 | 勾选后生成 `el-table-column` |
| 查询 `isQuery` + 查询方式 `queryType` | 是否出现在搜索表单，以及比较方式 | `EQ`（=）、`LIKE`、`BETWEEN` |
| 必填 `isRequired` | 表单是否必填，生成校验规则 | 生成 `rules` |
| 插入 / 编辑 | 是否出现在新增 / 修改表单 | 控制表单字段的范围 |
| 显示类型 `htmlType` | 表单控件类型 | 文本框 `input`、文本域 `textarea`、下拉框 `select`、单选 `radio`、复选 `checkbox`、日期 `datetime`、图片上传 `imageUpload`、文件上传 `fileUpload`、富文本 `editor` |
| 字典类型 `dictType` | 下拉、单选等选项来源 | 选择 `sys_user_sex` 等字典 |
| Java 类型 `javaType` | 后端实体属性类型 | `Long`、`String`、`Integer`、`Date` 等 |

查询方式的 `BETWEEN` 与第 28 课的 `addDateRange` 对应：日期范围查询会生成 `params[beginXxx]` 与 `params[endXxx]` 参数。

> 设计思考：字段配置是"一份元数据，多处复用"的思路。同一个 `htmlType` 既决定表单控件，也影响列表展示与校验规则，这与第 26、27 课的组件化思路一致。

#### （五）生成结果与本仓库目录的对应

生成的代码通常分为后端与前端两部分。以单表 `element-plus` 模板为例，前端文件的位置如下（以 RuoYi 约定为准）：

| 生成内容 | 本仓库中的位置 |
| --- | --- |
| 接口文件 | `src/api/{moduleName}/{businessName}.js`（第 22 课的接口模块化） |
| 列表页面 | `src/views/{moduleName}/{businessName}/index.vue` |
| 字典引用 | `useDict(...)`（第 29 课） |
| 菜单与权限 | 后端生成 SQL 中的菜单记录，决定路由与 `v-hasPermi` 标识（第 17–18 课） |

> 注意：生成代码后，前端页面需要的菜单与权限数据来自后端的菜单表。只放入文件而没有菜单记录，页面无法通过路由访问。

## 第 38 课：在线表单构建器

### 38.1 学习目标

- 理解表单构建器的三栏结构：左侧组件库、中间画布、右侧属性面板。
- 理解 `vuedraggable` 拖拽的数据流：从组件库拖入画布，克隆并生成唯一标识。
- 理解 `drawingDefault.js`、`config.js` 的组件配置数据结构。
- 理解 `html.js`、`js.js`、`css.js` 如何把配置转换为代码。

### 38.2 课前准备

- 进入"系统工具 → 表单构建"页面，观察三栏结构。
- 打开 `src/views/tool/build/index.vue`、`src/utils/generator/` 目录。

### 38.3 知识讲解

#### （一）三栏结构

`tool/build/index.vue` 的模板主要分为三块：

| 区域 | 组件 | 作用 |
| --- | --- | --- |
| 左侧 | 三个 `draggable`（`inputComponents`、`selectComponents`、`layoutComponents`） | 组件库：输入类、选择类、布局类 |
| 中间 | `draggable.drawing-board`，循环渲染 `draggable-item` | 画布：当前表单的组件列表 `drawingList` |
| 右侧 | `RightPanel`（`:active-data="activeData"`、`:form-conf="formConf"`） | 属性面板：编辑选中组件或整张表单的属性 |

#### （二）数据模型

整个设计器的核心数据是两个数组/对象：

- `drawingList`：画布上的组件数组，每一项是一个组件配置对象；
- `formConf`：表单级配置（如 `size`、`labelPosition`、`gutter`、`span` 等）。

一个组件配置的典型结构（来自 `drawingDefault.js` 的示例，已节选）：

```js
{
  layout: 'colFormItem',        // 布局类型：colFormItem 普通表单项；rowFormItem 行容器
  tagIcon: 'input',             // 左侧组件库中的图标名
  label: '手机号',               // 标签文字
  vModel: 'mobile',             // 绑定的数据字段名
  formId: 6,                    // 画布内的唯一 ID
  tag: 'el-input',              // 渲染的 Element Plus 组件
  placeholder: '请输入手机号',
  defaultValue: '',
  span: 24,                     // 栅格宽度
  required: true,
  regList: [{ pattern: '...', message: '手机号格式错误' }]   // 校验规则
}
```

- `tag` 决定渲染哪个组件，`vModel` 决定绑定哪个字段，`regList` 生成校验规则；
- 这种"配置即数据"的模型，是低代码的基础：界面只是配置的一种展示。

#### （三）拖拽：从组件库到画布

```js
function addComponent(item) {
  const clone = cloneComponent(item)  // 深拷贝
  drawingList.value.push(clone)
  activeFormItem(clone)               // 选中新组件，右侧属性面板切换
}

function cloneComponent(origin) {
  const clone = JSON.parse(JSON.stringify(origin))  // 深拷贝，避免修改组件库原始配置
  clone.formId = ++idGlobal.value                   // 生成递增 ID
  clone.span = formConf.value.span
  clone.renderKey = +new Date()                     // 改变 key 可强制重新渲染
  if (clone.layout === 'colFormItem') {
    clone.vModel = `field${idGlobal.value}`         // 自动生成唯一字段名
  }
  ...
}
```

要点：
- **深拷贝**（`JSON.parse(JSON.stringify(...))`）：组件库里的配置是模板，每次拖入都要得到独立副本；
- **唯一 ID**：`formId` 与 `vModel` 都基于 `idGlobal` 递增，避免重名；
- **`renderKey`**：修改后通过改变 `key` 强制重建组件，这是 Vue 中常用的"重置组件"手段。

`vuedraggable` 的 `group="componentsGroup"` 与 `:sort="false"` 控制：左侧组件库只能"拖出"，不能在库内排序；画布内部可以排序（第 8 课的组件通信）。

#### （四）配置到代码：生成的三部分

点击"复制代码"或"下载"后，`index.vue` 中的 `generateCode` 会调用：

```js
const script = vueScript(makeUpJs(formData.value, type))   // js.js：生成 <script>
const html = vueTemplate(makeUpHtml(formData.value, type)) // html.js：生成 <template>
const css = cssStyle(makeUpCss(formData.value))            // css.js：生成 <style>
return beautifier.html(html + script + css, beautifierConf.html) // 拼接后格式化
```

也就是说，最终输出是**一个完整的单文件 `.vue` 代码字符串**，复制与下载都使用它。

| 文件 | 职责 | 典型内容 |
| --- | --- | --- |
| `html.js` | 遍历 `drawingList`，把每个组件转换为模板字符串 | `<el-form-item label="手机号" prop="mobile">…</el-form-item>` |
| `js.js` | 生成 `data`（表单默认值）、`rules`（来自 `regList`）、`options` 等脚本 | `data() { return { mobile: '' } }`、校验规则数组 |
| `css.js` | 生成样式（如组件宽度 `style`） | `.el-input { width: 100% }` |

`render.js` 则负责**在设计器内部**渲染组件：它把配置对象通过 `h()` 渲染为真正的 Vue 组件，所以画布上的所见即所得，依赖的正是这份配置。

> 对比：生成的代码（`html.js`）与设计器内部渲染（`render.js`）是两条路径，都读取同一份配置。这就是"一份配置，两种输出"。

#### （五）弹窗组件

| 组件 | 作用 |
| --- | --- |
| `CodeTypeDialog.vue` | 选择生成类型：`file`（页面）或 `dialog`（弹窗）；需要下载时还可输入文件名（默认为时间戳加 `.vue`） |
| `IconsDialog.vue` | 选择图标，由右侧属性面板的 `prefix-icon`、`suffix-icon` 等属性打开 |
| `TreeNodeDialog.vue` | 编辑树形结构的数据，提交时通过 `commit` 事件返回表单数据（具体用途以相关组件调用为准） |

这些弹窗是设计器内部的自定义对话框，与第 30 课的 `$modal` 统一弹窗风格不同。其中 `IconsDialog` 通过 `v-model` 控制显隐，选中后触发 `select` 事件。

- 打开 `src/layout/components/HeaderNotice/DetailView.vue` 与 `src/components/HeaderSearch/index.vue`。

### 39.3 知识讲解

#### （一）性能

**1. 路由懒加载**

`src/router/index.js` 中的页面组件使用动态导入：

```js
{ path: '/login', component: () => import('@/views/login') }
```

- 动态导入使每个页面成为独立的代码块，首次进入登录页不需要下载后台页面的代码；
- 动态路由的页面由 `permission.js` 中的 `loadView` 按路径加载（`import.meta.glob('./../../views/**/*.vue')`），同样是懒加载（第 17 课）。

**2. 构建分包与产物命名**

`vite.config.js` 的 `build` 配置：

```js
build: {
  chunkSizeWarningLimit: 2000,           // 单个 chunk 超过 2000 KB 才警告
  rollupOptions: {
    output: {
      chunkFileNames: 'static/js/[name]-[hash].js',
      entryFileNames: 'static/js/[name]-[hash].js',
      assetFileNames: 'static/[ext]/[name]-[hash].[ext]'
    }
  }
}
```

- `[hash]` 让文件名随内容变化，配合浏览器缓存：内容不变则缓存有效，内容变化则自动更新；
- `chunkSizeWarningLimit` 调大只是**隐藏警告**，不是解决问题。真正的优化需要通过 `manualChunks` 把大依赖（如 ECharts、Element Plus）拆分出来，本项目目前未配置 `manualChunks`。

**3. 压缩**

`vite/plugins/compression.js` 根据环境变量 `VITE_BUILD_COMPRESS` 决定生成 `gzip` 或 `brotli` 压缩文件。`.env.production` 与 `.env.staging` 中设置为 `gzip`。压缩文件需要 Nginx 等服务器开启对应的静态文件输出（参见第 6 课）。

**4. keep-alive 缓存**

`AppMain` 中的 `<keep-alive :include="tagsViewStore.cachedViews">`（第 9 课）让已访问的页面保留状态，减少重复初始化的开销，但也会增加内存占用。

> 评估方法：`npm run build` 后，在 `dist/static/js/` 中查看文件大小，比较调整前后的差异。若要验证懒加载效果，可在浏览器 Network 面板中观察进入某页面时加载的 JS 文件。

#### （二）安全

**1. Token 存储位置**

`src/utils/auth.js` 中：

```js
const TokenKey = 'Admin-Token'
export function getToken() { return Cookies.get(TokenKey) }
```

- Token 保存在 Cookie 中（通过 `js-cookie` 读写），请求头中以 `Authorization: Bearer ...` 携带（第 21 课）；
- 这意味着 Token 可以被**页面中的任何 JS 读取**。如果存在 XSS 漏洞，攻击者可以直接窃取 Token；
- 改进方向：后端为 Cookie 设置 `HttpOnly`（JS 无法读取），但这要求后端改造，并需要 CSRF 防护；或使用更短的有效期加刷新机制。

**2. XSS 风险点**

项目中用 `v-html` 渲染动态内容的位置：

| 位置 | 渲染内容 | 风险 |
| --- | --- | --- |
| `layout/components/HeaderNotice/DetailView.vue` | `detail.noticeContent`（公告富文本，由管理员在编辑器中录入） | 富文本是 HTML，若含恶意脚本，会在所有查看者的浏览器中执行 |
| `components/HeaderSearch/index.vue` | `highlightText(...)` 的结果（菜单标题与路径） | `highlightText` 只对**搜索关键词**做了正则转义，**没有转义原文本**，因此原文中的 HTML 标签会被当作 HTML 渲染 |

第二个风险点值得关注：`highlightText` 中

```js
const keyword = escapeRegExp(search.value)           // 关键词被转义
return text.replace(reg, '<span class="highlight">$1</span>')  // 原文 text 未转义
```

在当前数据来源（路由与菜单标题）下风险较低，但如果菜单名来自可由用户修改的数据，就可能形成存储型 XSS。

**3. 接口防重复提交**

`request.js` 的请求拦截器对 `post`、`put` 请求做了重复提交检测（第 21 课）：

- 对比 URL、数据内容与时间间隔（默认 1000 ms），相同请求在间隔内会被拒绝；
- 通过 `repeatSubmit: false` 可关闭检测；
- 请求数据超过 5 MB 时跳过检测，并给出控制台警告。

这是**体验层**的防护：它只能拦截前端的快速重复点击，不能防止恶意的并发请求，真正的幂等性需要后端保证。

**4. 前端权限的局限**

- `v-hasPermi`、路由守卫与动态菜单只是**隐藏入口**，攻击者可以直接调用接口；
- 因此，**所有权限判断必须在后端再次执行**，这是本项目的安全底线（第 18 课）。

**5. 前端加密的边界**

第 29 课已讨论：`jsencrypt.js` 中的私钥位于前端代码，加密只能起混淆作用。

#### （三）可维护性

**1. 分层**

| 层 | 位置 | 职责 |
| --- | --- | --- |
| 接口层 | `src/api/**` | 只描述请求，不含页面逻辑 |
| 请求层 | `src/utils/request.js` | 统一的拦截、错误处理 |
| 状态层 | `src/store/**` | 全局共享状态（用户、路由、字典、设置） |
| 视图层 | `src/views/**`、`src/components/**` | 页面与组件，通过 store 与 api 协作 |

分层的价值在于：**修改后端地址或错误处理时，只需改一处，页面代码无需变化**。

**2. 统一封装**

- 请求：`request.js`；
- 弹窗与消息：`$modal`（第 30 课）；
- 字典：`useDict`（第 29 课）；
- 表格分页、工具栏、树面板等通用组件（第 26、27 课）。

统一封装减少了"每个页面各写一套"的重复代码，也让风格保持一致。

**3. 命名与职责边界**

- 页面文件统一为 `index.vue`，子页面按功能命名（如 `authRole.vue`、`selectUser.vue`）；
- 组件职责单一：`Pagination` 只负责分页，`DictTag` 只负责展示字典值，`IconSelect` 只负责选图标；
- 一个值得改进的地方：部分页面（如用户页）的代码较长，可以把"表单弹窗"、"搜索表单"拆为子组件。

#### （四）国际化思路

- 当前项目的文案直接写在模板中，以中文为主，没有接入 `vue-i18n`（在 `src` 中检索未发现 `createI18n` 或 `$t(`）；
- 扩展思路：
  1. 引入 `vue-i18n`，把文案抽离到 `locales/zh-CN.js`、`locales/en-US.js`；
  2. Element Plus 通过 `locale` 切换内置文案（`main.js` 中目前固定为 `zh-cn`）；
  3. 日期格式、数字格式使用 `Intl` API，与语言绑定；
  4. 注意后端返回的提示文字也需要国际化方案（前端映射错误码，第 22 课）。

> 问题二：修改后列表没有刷新。原因是提交成功后忘记调用 `getList()`。解决：参照用户页的写法，在成功回调中关闭弹窗并刷新列表。
> 若重来：会先与后端对齐字段名并写入接口文档，再开始页面开发，减少返工。
