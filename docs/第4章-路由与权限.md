### 15.2 课前准备

- 阅读 Vue Router 官方文档的"动态路由匹配"与"嵌套路由"章节（<https://router.vuejs.org/zh/>）。

### 15.3 知识讲解

#### （一）创建路由实例

```js
const router = createRouter({
  history: createWebHistory(),
  routes: constantRoutes,
  scrollBehavior(to, from, savedPosition) {
    if (savedPosition) return savedPosition   // 浏览器前进/后退时恢复滚动位置
    return { top: 0 }                         // 普通跳转回到顶部
  },
})
```

- **`createWebHistory()`**：使用 HTML5 History API，URL 形如 `/system/user`，没有 `#`。这种模式美观，但要求服务器对所有路径回退到 `index.html`（第 6 课已讲）。
- **`routes: constantRoutes`**：初始只注册静态路由；动态路由在登录后再注册（第 17 课）。
- **`scrollBehavior`**：控制路由切换时的滚动位置。

#### （二）静态路由与动态路由

| 类型 | 变量 | 何时注册 | 典型内容 |
| --- | --- | --- | --- |
| 静态路由 | `constantRoutes` | 应用启动时（createRouter 时） | 登录、注册、404、401、首页、锁屏、个人中心 |
| 动态路由 | `dynamicRoutes` | 登录并拉取权限后（按权限过滤） | 分配角色、分配用户、字典数据、调度日志、修改生成配置 |

注意两点：

1. `constantRoutes` 中的首页（`/index`）所在的 `Layout` 是**所有后台页面的容器**，它包含侧边栏、顶栏与主内容区（第 24 课）。
2. `dynamicRoutes` 中的大部分路由 `hidden: true`，即**不出现在侧边栏**，它们是某些菜单页面的"子页面"，例如"分配角色"从"用户管理"的操作按钮进入。

#### （三）路由字段速查（来自 `router/index.js` 注释）

| 字段 | 位置 | 含义 | 示例 |
| --- | --- | --- | --- |
| `hidden` | 路由顶层 | 不在侧边栏显示 | 登录页、404、分配角色页 |
| `alwaysShow` | 路由顶层 | 有多个子路由时，仍以嵌套形式显示根菜单 | 组件页面等目录型菜单 |
| `redirect` | 路由顶层 | 访问父路由时的重定向目标；`noRedirect` 表示面包屑不可点击 | `redirect: '/index'` |
| `name` | 路由顶层或子路由 | 路由名称，`keep-alive` 缓存依赖它与组件名 | `name: 'Index'` |
| `component` | 路由顶层或子路由 | 页面组件，可为 `Layout` 或懒加载的页面 | `() => import('@/views/...')` |
| `meta.title` | `meta` | 侧边栏与面包屑显示的名称；标签页标题 | `'首页'` |
| `meta.icon` | `meta` | 菜单图标，对应 `src/assets/icons/svg` | `'dashboard'` |
| `meta.noCache` | `meta` | `true` 时页面不被 `keep-alive` 缓存 | 不缓存的编辑页 |
| `meta.breadcrumb` | `meta` | `false` 时不在面包屑中显示 | 个别过渡页 |
| `meta.activeMenu` | `meta` | 访问该页面时高亮的侧边栏菜单路径 | `'/system/user'` |
| `meta.affix` | `meta` | 固定标签（不可关闭） | 首页 |
| `permissions` | 动态路由顶层 | 访问该路由需要的权限标识列表（满足任一即可） | `['system:user:edit']` |
| `roles` | 动态路由顶层 | 访问该路由需要的角色列表 | `['admin']` |

> 注意：路由配置中写的是 `noRedirect`，而 `/user` 路由里写成了 `redirect: 'noredirect'`（小写）。两者在 Vue Router 中的含义都是"没有重定向"，但严格来说大小写不同的字符串可能被处理为不同值，这是阅读时值得留意的细节。

#### （四）动态参数与正则约束

项目中有多个带参数的路由：

```js
{ path: 'role/:userId(\\d+)',    name: 'AuthRole', ... }   // 分配角色，参数必须为数字
{ path: 'index/:dictId(\\d+)',   name: 'Data',     ... }   // 字典数据
{ path: 'profile/:activeTab?',   name: 'Profile',  ... }   // 可选参数
```

- `:userId` 是**必填参数**，访问时 `route.params.userId` 可读取。
- `(\\d+)` 是**正则约束**：只有纯数字才能匹配，`/system/user-auth/role/abc` 会匹配失败，从而落到 404。
- `:activeTab?` 是**可选参数**：`/user/profile` 与 `/user/profile/resetPwd` 都能访问。

在页面中读取参数：

```js
import { useRoute } from 'vue-router'
const route = useRoute()
const userId = route.params.userId
```

> 注意：`useRoute()` 返回的是响应式对象，但如果你直接解构 `const { userId } = route.params`，结果不会随路由变化而更新。需要响应式时，应使用 `computed(() => route.params.userId)` 或 `watch`。

#### （五）嵌套路由与 `Layout`

```js
{
  path: '/system/user-auth',        // 父路由：Layout 作为容器
  component: Layout,
  hidden: true,
  permissions: ['system:user:edit'],
  children: [
    { path: 'role/:userId(\\d+)', component: () => import('@/views/system/user/authRole'), name: 'AuthRole', meta: {...} }
  ]
}
```

- 父路由的 `component` 是 `Layout`，它负责渲染侧边栏、顶栏等外壳；子路由的组件渲染在 `Layout` 内部的 `<router-view>` 中。
- 子路由的 `path` 会自动拼接父路由路径，即最终路径为 `/system/user-auth/role/:userId`。

#### （六）懒加载：`() => import(...)`

所有页面组件都使用箭头函数包裹的 `import()`：

```js
component: () => import('@/views/login')
```

这是**路由懒加载**：页面代码只在首次访问时下载，不会全部打包进首屏。它是性能优化的基础，我们在第 6 课看到的多个 chunk 正是来自这里。

<summary>参考答案（先自己思考再查看）</summary>

1. History 模式 URL 形如 `/path`，Hash 模式形如 `/#/path`。History 模式需要服务器对所有路径返回 `index.html`，否则刷新会 404。

5. 路由懒加载，页面代码只在访问时才加载，减小首屏体积，提升加载速度。

### 16.2 课前准备

- 准备一张"判断分支树"纸张，边读边画。

### 16.3 知识讲解

#### （一）守卫的执行时机与返回值

`router.beforeEach` 在**每次路由跳转前**执行，它的返回值决定跳转行为：

| 返回值 | 含义 |
| --- | --- |
| `true` 或 `undefined` | 允许跳转 |
| `false` | 取消跳转（当前页面不变） |
| 路径字符串，如 `'/login'` | 重定向到该路径 |
| 路由对象，如 `{ path: '/', replace: true }` | 重定向并可指定参数 |

守卫可以是 `async` 函数，此时 Vue Router 会等待 Promise 完成后再决定跳转。`permission.js` 正是利用了这一点。

#### （二）`permission.js` 逐段解读

整个守卫的逻辑可以分为四个分支。下面按代码顺序说明（代码有删减）：

```js
const whiteList = ['/login', '/register']

router.beforeEach(async (to, from) => {
  NProgress.start()                                    // ① 顶部进度条开始

  if (getToken()) {                                    // ② 有 Token：已登录（或曾经登录）
    to.meta.title && useSettingsStore().setTitle(to.meta.title)
    const isLock = useLockStore().isLock

    if (to.path === '/login') {                        // ②-a 已登录还访问登录页 → 回首页
      NProgress.done()
      return { path: '/' }
    }
    if (isWhiteList(to.path)) return true              // ②-b 白名单（如注册页）直接放行

    if (isLock && to.path !== '/lock') {               // ②-c 已锁屏：强制去锁屏页
      NProgress.done()
      return { path: '/lock' }
    }
    if (!isLock && to.path === '/lock') {              // ②-d 未锁屏却访问锁屏页 → 回首页
      NProgress.done()
      return { path: '/' }
    }

    if (useUserStore().roles.length === 0) {           // ②-e 有 Token 但没拉过权限（如刷新页面）
      isRelogin.show = true
      try {
        await useUserStore().getInfo()                 // 获取用户信息与权限
        isRelogin.show = false
        const accessRoutes = await usePermissionStore().generateRoutes()   // 生成动态路由
        accessRoutes.forEach(route => {
          if (!isHttp(route.path)) router.addRoute(route)                 // 注册到路由表
        })
        return { ...to, replace: true }                // 重新导航，确保新路由生效
      } catch (err) {
        await useUserStore().logOut()                  // 失败：退出登录
        ElMessage.error(err)
        return { path: '/' }
      }
    }
    return true                                        // ②-f 其它情况：正常放行
  } else {                                             // ③ 没有 Token：未登录
    if (isWhiteList(to.path)) return true              // ③-a 白名单直接进入
    NProgress.done()
    return `/login?redirect=${to.fullPath}`            // ③-b 其它全部去登录页，并记录原目标
  }
})

router.afterEach(() => { NProgress.done() })           // ④ 跳转结束后收尾
```

各分支的业务含义：

| 分支 | 场景 | 处理 |
| --- | --- | --- |
| ② 有 Token | 用户已登录 | 进入下面的细分逻辑 |
| ②-a | 已登录仍访问登录页 | 回首页，避免重复登录 |
| ②-c / ②-d | 锁屏相关 | 锁定时只能去锁屏页；解锁后不能停留在锁屏页 |
| ②-e | 有 Token 但 `roles` 为空 | 通常是**刷新页面后**，Pinia 内存数据已清空，需要重新拉取用户信息与菜单 |
| ③ 无 Token | 未登录 | 白名单放行，其它跳登录页并带上 `redirect` 参数 |

#### （三）为什么刷新页面要重新拉取权限

第 3 课讲过，`user` store 的 `roles` 与 `permissions` 只在内存中。刷新页面后：

- Token 仍在 Cookie 中（`Admin-Token`），所以守卫判断"已登录"；
- 但 `roles` 为空，所以需要调用 `getInfo()` 和 `generateRoutes()`；
- 动态路由（`router.addRoute`）也随页面刷新一起丢失，需要重新注册。

这正是守卫中 **②-e 分支** 存在的原因，它保证了"刷新后页面仍然可用"。

#### （四）`return { ...to, replace: true }` 的意义

动态路由注册完成后，当前的 `to` 可能还没有被匹配（因为它是在注册之前计算的）。所以需要：

```js
return { ...to, replace: true }
```

它表示"用相同的目标，重新导航一次"，并用 `replace` 替换历史记录，避免用户回退到一个中间状态。

#### （五）白名单与路径匹配

```js
const whiteList = ['/login', '/register']
const isWhiteList = (path) => whiteList.some(pattern => isPathMatch(pattern, path))
```

`isPathMatch` 来自 `src/utils/validate.js`，它把模式字符串转为正则，支持 `*`（匹配单段）与 `**`（匹配多段）。例如：

- `'/login'` 只匹配 `/login`；
- `'/public/*'` 可以匹配 `/public/a`，但不匹配 `/public/a/b`；
- `'/public/**'` 可以匹配多层路径。

> 安全提醒：白名单只影响**前端**的跳转，后端接口仍需自己做鉴权。

#### （六）`redirect` 参数的回跳

未登录访问 `/system/user` 时，守卫返回 `/login?redirect=/system/user`。登录成功后，登录页读取 `redirect` 参数并跳回原页面。这是一个常见的"登录后回跳"体验设计。

#### （七）`isRelogin` 与 401 处理

- `isRelogin` 是从 `request.js` 导出的状态对象（`{ show: false }`）。守卫在拉取权限期间把它的 `show` 设为 `true`，用于标记"正在处理登录状态"，避免 401 拦截器重复弹出重新登录的确认框。
- 当接口返回 401（登录过期），`request.js` 中的响应拦截器会弹出确认框，用户可选择重新登录（第 21 课会详细讲）。

### 17.2 课前准备

### 17.3 知识讲解

#### （一）整体流程

```
getRouters() ──► 后端菜单树 JSON
   │
   ▼  深拷贝三份（sdata / rdata / defaultData）
   │
   ├─► filterAsyncRouter(sdata)           → sidebarRouters（侧边栏）
   ├─► filterAsyncRouter(rdata, false, true) → routes（路由，含 filterChildren 扁平化）
   └─► filterAsyncRouter(defaultData)     → topbarRouters（顶部导航）
   │
   ▼
filterDynamicRoutes(dynamicRoutes)  → 按权限筛选出的动态路由
   │
   ▼
asyncRoutes.forEach(route => router.addRoute(route))
   │
   ▼
返回 rewriteRoutes → 守卫中再次 router.addRoute 注册
```

#### （二）`getRouters` 返回的数据结构

后端返回的菜单树大致如下（结构示意，字段以实际接口为准）：

```json
{
  "code": 200,
  "data": [
    {
      "name": "System",
      "path": "/system",
      "component": "Layout",
      "hidden": false,
      "meta": { "title": "系统管理", "icon": "system", "noCache": true },
      "children": [
        {
          "name": "User",
          "path": "user",
          "component": "system/user/index",
          "meta": { "title": "用户管理", "icon": "user" }
        }
      ]
    }
  ]
}
```

关键字段：

| 字段 | 含义 |
| --- | --- |
| `path` | 路由路径；子路由通常是相对路径 |
| `component` | **字符串**：`'Layout'`、`'ParentView'`、`'InnerLink'` 为特殊组件，其它为 `views` 下的相对路径（不含 `views/` 与 `.vue`） |
| `children` | 子菜单 |
| `meta` | 标题、图标等元信息，与本地路由配置的 `meta` 结构一致 |
| `hidden` | 是否在侧边栏隐藏 |

> **思考**：为什么后端返回的是字符串 `"system/user/index"` 而不是组件本身？因为 JSON 无法序列化组件对象，所以前端需要自己把字符串映射为组件（即 `loadView`）。

#### （三）三次 `filterAsyncRouter` 的分工

`generateRoutes` 中对同一份数据做了三次处理，因为它们服务于不同的 UI 或路由：

| 调用 | 结果 | 用途 |
| --- | --- | --- |
| `filterAsyncRouter(sdata)` | `sidebarRouters` | 侧边栏渲染（保留层级结构） |
| `filterAsyncRouter(rdata, false, true)` | `rewriteRoutes`（即 `routes`） | 注册到路由表（`type=true` 时会调用 `filterChildren` 扁平化） |
| `filterAsyncRouter(defaultData)` | `topbarRouters` | 顶部导航模式（`navType` 为 2、3 时使用） |

**为什么要深拷贝**：`filterAsyncRouter` 会**直接修改传入对象**，例如把字符串 `component` 替换为组件函数，并删除空的 `children`。如果三次处理共用同一份对象，第二次处理时拿到的已经是被修改后的数据，结果会出错。因此代码使用 `JSON.parse(JSON.stringify(res.data))` 做了三份独立副本。

> 注意：`JSON.parse(JSON.stringify(...))` 会丢失 `undefined`、函数等非 JSON 值，但菜单数据本身都是纯 JSON，所以这里是安全的。

#### （四）`filterAsyncRouter`：字符串到组件的转换

```js
function filterAsyncRouter(asyncRouterMap, lastRouter = false, type = false) {
  return asyncRouterMap.filter(route => {
    if (type && route.children) {
      route.children = filterChildren(route.children)        // 扁平化（仅 routes 使用）
    }
    if (route.component) {
      if (route.component === 'Layout') route.component = Layout
      else if (route.component === 'ParentView') route.component = ParentView
      else if (route.component === 'InnerLink') route.component = InnerLink
      else route.component = loadView(route.component)       // 字符串 → 懒加载函数
    }
    if (route.children != null && route.children.length) {
      route.children = filterAsyncRouter(route.children, route, type)   // 递归
    } else {
      delete route['children']
      delete route['redirect']
    }
    return true
  })
}
```

要点：

1. **特殊组件**：`Layout`、`ParentView`、`InnerLink` 是框架内置组件，直接替换；
2. **普通页面**：交给 `loadView` 映射；
3. **递归处理**：子节点同样需要转换；
4. **清理无用字段**：没有子节点时删除 `children` 和 `redirect`，避免路由配置冲突。

#### （五）`filterChildren`：扁平化的子路由

```js
function filterChildren(childrenMap, lastRouter = false) {
  var children = []
  childrenMap.forEach(el => {
    el.path = lastRouter ? lastRouter.path + '/' + el.path : el.path
    if (el.children && el.children.length && el.component === 'ParentView') {
      children = children.concat(filterChildren(el.children, el))   // ParentView 下的子节点继续展开
    } else {
      children.push(el)
    }
  })
  return children
}
```

`ParentView` 是一个"只起分组作用的父级"，它本身不渲染页面。`filterChildren` 把它的子节点提到同一层，并拼接完整路径。这样在路由表中，子路由可以直接挂在 `Layout` 下，避免多余的嵌套层级。

#### （六）`loadView`：字符串到组件的映射

```js
const modules = import.meta.glob('./../../views/**/*.vue')   // 构建时收集所有 views 下的 .vue 文件

export const loadView = (view) => {
  let res
  for (const path in modules) {
    const dir = path.split('views/')[1].split('.vue')[0]       // 如 'system/user/index'
    if (dir === view) {
      res = () => modules[path]()                              // 返回懒加载函数
    }
  }
  return res
}
```

- `import.meta.glob` 是 Vite 提供的**批量导入**功能。它在构建时把匹配的文件生成为一个对象：键是路径，值是懒加载函数。
- `loadView` 把 `'system/user/index'` 与键中的 `views/` 之后的部分进行比对。
- **常见错误**：如果后端的 `component` 写成 `'system/user/index.vue'` 或 `'/system/user/index'`，比对会失败，导致页面无法加载。

#### （七）`router.addRoute`：注册动态路由

```js
accessRoutes.forEach(route => {
  if (!isHttp(route.path)) {
    router.addRoute(route)
  }
})
```

- `router.addRoute(route)` 在运行时向路由表追加一条路由。
- `isHttp(route.path)` 为真时跳过，因为外链（如 `https://...`）不需要作为本地路由注册，它们通过 `InnerLink` 组件打开。

#### （八）`generateRoutes` 中的动态路由

```js
const asyncRoutes = filterDynamicRoutes(dynamicRoutes)   // 按权限过滤
asyncRoutes.forEach(route => { router.addRoute(route) })
this.setRoutes(rewriteRoutes)                            // 保存到 store，供侧边栏等使用
```

这一步是把本地定义的动态路由（第 15 课的 `dynamicRoutes`）与后端返回的菜单路由**合并**注册到同一个路由表中。

#### （九）`setRoutes` 等 setter 的作用

| 方法 | 写入的状态 | 用途 |
| --- | --- | --- |
| `setRoutes(routes)` | `addRoutes`、`routes` | 完整路由列表（`routes` = 静态 + 动态） |
| `setSidebarRouters(routes)` | `sidebarRouters` | 侧边栏菜单数据（含静态首页等） |
| `setDefaultRoutes(routes)` | `defaultRoutes` | 默认路由数据 |
| `setTopbarRoutes(routes)` | `topbarRouters` | 顶部导航数据 |

### 18.3 知识讲解

#### （一）权限的两个维度

| 维度 | 作用 | 示例 |
| --- | --- | --- |
| **权限标识（permission）** | 细粒度，控制具体操作（按钮、接口） | `system:user:add`、`system:user:edit` |
| **角色（role）** | 粗粒度，控制身份（如管理员、普通用户） | `admin`、`common` |

命名规范：权限标识采用 **`模块:子模块:动作`** 的格式，例如 `system:user:remove` 表示"系统管理 → 用户 → 删除"。

超级权限：

- 权限标识 `*:*:*` 表示拥有所有权限；
- 角色 `admin` 视为超级管理员，拥有全部角色的效果。

这两条规则在 `auth.js`、`hasPermi.js`、`hasRole.js` 中都有体现。

#### （二）`v-hasPermi`：按钮级权限指令

```vue
<el-button type="primary" icon="Plus" @click="handleAdd" v-hasPermi="['system:user:add']">新增</el-button>
```

实现（`src/directive/permission/hasPermi.js`）：

```js
mounted(el, binding) {
  const { value } = binding                                   // ['system:user:add']
  const permissions = useUserStore().permissions
  const hasPermissions = permissions.some(permission =>
    all_permission === permission || value.includes(permission))
  if (!hasPermissions) {
    el.parentNode && el.parentNode.removeChild(el)            // 没有权限：直接从 DOM 移除
  }
}
```

关键细节：

- 指令在 `mounted` 阶段判断，**只执行一次**；
- 没有权限时**从 DOM 中删除**，而不是 `display: none`，因此用户无法通过修改 CSS 显示它；
- 若值不是非空数组，会直接抛出错误：`请设置操作权限标签值`。

> **注意**：`v-hasPermi` 只在元素挂载时判断。如果用户的权限在页面打开后发生变化，按钮不会自动出现或消失，需要刷新页面。

#### （三）`v-hasRole`：角色级指令

```vue
<el-button v-hasRole="['admin']">超级管理员专属</el-button>
```

逻辑与 `v-hasPermi` 相同，只是比对的对象是 `roles` 而不是 `permissions`，且同样支持 `admin` 超级角色。

#### （四）脚本中的权限判断：`auth` 插件

`src/plugins/auth.js` 提供了一组函数，用于在 `<script>` 中做判断：

| 方法 | 含义 |
| --- | --- |
| `auth.hasPermi(perm)` | 拥有单个权限 |
| `auth.hasPermiOr([...])` | 拥有其中任意一个（OR） |
| `auth.hasPermiAnd([...])` | 同时拥有全部（AND） |
| `auth.hasRole(role)` | 拥有单个角色 |
| `auth.hasRoleOr([...])` | 拥有其中任意一个角色 |
| `auth.hasRoleAnd([...])` | 同时拥有全部角色 |

示例：

```js
import auth from '@/plugins/auth'

if (auth.hasPermi('system:user:export')) {
  // 显示导出相关逻辑
}
```

**指令与函数的选择**：
- 控制**模板中元素是否存在** → 用指令 `v-hasPermi` / `v-hasRole`；
- 控制**脚本中的逻辑分支**（如是否发起某个请求、是否显示某个变量）→ 用 `auth` 函数。

#### （五）`utils/permission.js` 的 `checkPermi` 与 `checkRole`

这两个函数是与 `auth` 对应的**纯函数版本**，供不适合用插件的场景使用（如在工具函数中）。它们的逻辑与指令一致，区别在于不依赖插件注册。

> 阅读时的小提示：`checkPermi` 在参数不合法时会打印一条 `console.error`，提示格式应为 `checkPermi="['system:user:add','system:user:edit']"`。这段提示信息是从模板语法中复制过来的，与 JS 调用方式略有差异，阅读时要以代码为准。

#### （六）动态路由的权限过滤

`dynamicRoutes`（第 15 课）中的路由通过 `permissions` 或 `roles` 字段声明需要的权限：

```js
{ path: '/system/user-auth', permissions: ['system:user:edit'], ... }
```

`filterDynamicRoutes` 会：

```js
if (route.permissions) {
  if (auth.hasPermiOr(route.permissions)) res.push(route)   // 满足任一即可注册
} else if (route.roles) {
  if (auth.hasRoleOr(route.roles)) res.push(route)
}
```

- 没有权限的动态路由**根本不会被注册**，访问地址会落到 404；
- 这与"按钮隐藏"不同：按钮隐藏只是界面层面，路由不注册则访问也被阻止。

#### （七）前端权限的局限性

前端权限控制的目的是**改善体验**：不让用户看到不能用的按钮与菜单。但它**不是安全边界**，原因包括：

1. 用户可以通过开发者工具修改 `permissions` 数据，或直接调用接口；
2. 前端隐藏的按钮，接口依然可以请求成功；
3. 路由过滤可以被绕过，直接访问页面组件的代码仍然存在于产物中（只是未注册路由）。

因此，**真正的权限校验必须在后端完成**：每个接口都要检查当前用户是否拥有对应权限。前端的权限代码只是"第一道提示"，后端才是"最后一道防线"。

3. `auth.hasPermiOr` 与 `auth.hasPermiAnd` 的区别是什么？
4. 动态路由没有权限时，用户访问它会得到什么结果？这与按钮隐藏有何不同？
5. 为什么说前端权限不是安全边界？真正的防线在哪里？

<details>
<summary>参考答案（先自己思考再查看）</summary>

1. 依次为模块（system）、子模块（user）、动作（edit）。
2. 只隐藏（如 `display:none`）时元素仍在 DOM 中，用户可以通过修改样式或调试工具显示它；直接删除则无法通过常规手段恢复。
3. `Or` 表示满足其中任意一个即可，`And` 表示必须全部满足。
4. 该路由不会被注册到路由表，访问地址会落到 404。按钮隐藏只影响界面，而路由未注册则连访问地址都无效。
5. 因为前端代码与数据都可以被用户修改，接口也可以被直接调用。真正的权限校验必须在后端接口中完成，前端只负责改善体验。

</details>

- 能区分 `InnerLink`（外链页）与 `iFrame`（内嵌页）两种外部页面的实现。

### 19.2 课前准备

- 阅读 `src/views/redirect/index.vue`、`src/utils/dynamicTitle.js`。

### 19.3 知识讲解

#### （一）`$tab`：标签页与导航的统一入口

`src/plugins/tab.js` 把"路由跳转"与"标签页状态"两件事封装在一起。页面中推荐使用它，而不是直接调用 `router.push`，否则标签栏可能与实际页面不同步。

| 方法 | 作用 | 典型场景 |
| --- | --- | --- |
| `openPage(title, url, params)` | 添加标签并跳转到 `url` | 从一个页面打开另一个页面 |
| `closePage(obj)` | 关闭指定标签（默认当前页），并跳到最后一个标签 | 表单提交成功后关闭 |
| `closeOpenPage(obj)` | 关闭当前标签，并打开新页面 `obj` | 编辑完成后跳回列表 |
| `refreshPage(obj)` | 刷新当前或指定页面 | 数据变化后刷新 |
| `closeAllPage()` | 关闭全部标签 | 退出时 |
| `closeLeftPage` / `closeRightPage` / `closeOtherPage` | 关闭左侧、右侧、其它标签 | 右键菜单 |
| `updatePage(obj)` | 更新标签信息（如标题） | 详情页标题变化 |

示例：

```js
import tab from '@/plugins/tab'

// 从用户列表打开"分配角色"页面，标签标题为"分配角色"
tab.openPage('分配角色', `/system/user-auth/role/${row.userId}`)
```

#### （二）`openPage` 的实现

```js
openPage(title, url, params) {
  const obj = { path: url, meta: { title: title } }
  useTagsViewStore().addView(obj)                  // 1. 先添加标签（visited + cached）
  return router.push({ path: url, query: params })  // 2. 再跳转
}
```

顺序很重要：先在标签栏中登记，再导航，这样用户看到页面切换时标签已经存在。

#### （三）`refreshPage`：通过 `/redirect` 中转重建组件

`keep-alive` 缓存的组件无法通过普通方式"刷新"。`refreshPage` 采用的策略是：

```
① 从 cachedViews 中删除当前组件名  →  keep-alive 将不再保留旧实例
② router.replace('/redirect' + 当前路径)  →  跳到中转页
③ /redirect/:path 页面 (src/views/redirect/index.vue) 执行 replace(path)
④ 目标页面重新挂载 → 新实例 → 数据重新加载
```

关键代码：

```js
refreshPage(obj) {
  // 防止在重定向过程中重复刷新
  if (path.startsWith('/redirect/')) return Promise.resolve()
  // 找到当前页组件的 name（若未指定 obj）
  return useTagsViewStore().delCachedView(obj).then(() => {
    router.replace({ path: '/redirect' + path, query })
  })
}
```

中转页 `src/views/redirect/index.vue` 的作用是：读取 `params.path`，再通过 `router.replace` 跳回原路径。由于中间经过了一次路由切换，组件被重新创建。

> **设计启示**：这是一个"用路由切换模拟组件重建"的技巧。它的代价是地址栏会短暂经过 `/redirect/...`，但对用户几乎不可见。

#### （四）`closePage` 与 `closeOpenPage` 的判断

`closePage()` 在不传参数时关闭当前页，并在关闭后跳转到最后一个标签页：

```js
closePage(obj) {
  if (obj === undefined) {
    return useTagsViewStore().delView(router.currentRoute.value).then(({ visitedViews }) => {
      const latestView = visitedViews.slice(-1)[0]       // 最后一个标签
      // ... 跳转到 latestView 或首页
    })
  }
}
```

这解释了为什么"关闭当前标签"后，页面不会停在空白，而是跳到另一个已打开的标签。

#### （五）动态标题：`useDynamicTitle`

```js
export function useDynamicTitle() {
  const settingsStore = useSettingsStore()
  if (settingsStore.dynamicTitle) {
    document.title = settingsStore.title + ' - ' + defaultSettings.title
  } else {
    document.title = defaultSettings.title
  }
}
```

- `settingsStore.title` 来自路由的 `meta.title`（由守卫中 `setTitle` 设置）；
- `settingsStore.dynamicTitle` 是设置项，决定是否显示"页面名 - 系统名"的格式；
- 关闭时只显示系统标题。

#### （六）外部页面的两种形式

| 形式 | 实现 | 特点 | 典型场景 |
| --- | --- | --- | --- |
| **外链（InnerLink）** | 路由 `component: 'InnerLink'`，`meta.link` 为外部地址 | 在本系统布局内，通过 iframe 打开 | 把外部文档、监控页面集成为菜单 |
| **内嵌（iFrame）** | `components/iFrame/index.vue`，由 `IframeToggle` 管理 | 把外部页面嵌入布局，保留导航 | 如 Druid 连接池监控（`monitor/druid`） |

**外链的关键字段**：

- `isHttp(route.path)` 为真的路由不会被 `router.addRoute` 注册（第 17 课）；
- 对于带 `meta.link` 的路由，`AppMain.vue` 中 `v-if="!route.meta.link"` 会跳过普通组件渲染，改由 `IframeToggle` 负责展示 iframe；
- `addIframeView` 会把路由加入 `iframeViews`，这样 iframe 页面也能像普通标签一样被管理。

`AppMain.vue` 中的相关代码：

```js
function addIframe() {
  if (route.meta.link) {
    useTagsViewStore().addIframeView(route)
  }
}
```

> **注意**：iframe 中的页面与本系统是不同源的，它们之间不能直接共享 Pinia 状态或 Cookie（取决于域名）。这一点在集成外部系统时需要特别留意。

#### （七）`validate.js` 中的 URL 判断工具

| 函数 | 作用 |
| --- | --- |
| `isHttp(url)` | 是否包含 `http://` 或 `https://`，用于判断外链 |
| `isExternal(path)` | 是否为外部协议（`http`、`https`、`mailto`、`tel`），用于菜单跳转逻辑 |
| `isPathMatch(pattern, path)` | 路径模式匹配（第 16 课） |

3. `refreshPage` 为什么要先删除缓存，再通过 `/redirect` 跳转？
4. `closePage()` 关闭当前标签后，为什么会跳到另一个标签？
5. 外链页面与内嵌页面在 `AppMain` 中分别如何处理？

<details>
<summary>参考答案（先自己思考再查看）</summary>

1. `$tab` 同时维护标签栏状态与路由跳转，避免标签与页面不同步；直接 `router.push` 不会更新标签栏（除非另外处理）。
2. 先登记标签，用户看到页面切换时标签已存在，体验一致；同时 `addView` 同步加入缓存，保证新页面可以被 `keep-alive` 正确缓存。
3. 不删除缓存，`keep-alive` 会复用旧实例，中转跳转也无法重建组件。先删除缓存，再经过 `/redirect` 切换，才能让组件真正重新创建。
4. `closePage` 调用 `delView` 后，取标签列表的最后一项作为新的目标，从而避免停留在已关闭页面的空白状态。
5. 带 `meta.link` 的路由在 `AppMain` 中跳过普通组件渲染（`v-if="!route.meta.link"`），并通过 `addIframe` 加入 `iframeViews`，由 iframe 组件负责展示；普通页面则直接渲染组件并参与缓存。

</details>
