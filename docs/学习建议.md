# RuoYi-Vue3 学习建议

> 本文档面向想要深入学习本仓库（若依管理系统 v3.9.2 前端，Vue 3 + Element Plus + Vite）的读者，给出阅读顺序、学习路径、动手练习和常见坑。

## 一、先建立整体认识

### 1. 这是什么仓库

- 这是 **纯前端仓库**，技术栈：Vue 3.5 + Vue Router 4 + Pinia 3 + Element Plus 2 + Vite 6 + Axios。
- 它需要配合 **后端仓库**（RuoYi-Vue / RuoYi-Vue-fast，SpringBoot）才能完整运行。开发环境下，`vite.config.js` 将 `/dev-api` 代理到 `http://localhost:8080`，所以学习前最好把后端也跑起来。
- 本仓库还有 TypeScript 版本（分支 `typescript`）和 Vue2 版本，可以在理解本版本后对比学习。

### 2. 先跑起来，再读代码

```bash
yarn --registry=https://registry.npmmirror.com   # 或 npm install
yarn dev                                          # 启动开发服务器（端口 80）
yarn build:prod                                   # 生产构建
```

建议步骤：

1. 启动后端（默认 8080 端口）和前端，用 `admin / admin123` 登录。
2. 逐个点开侧边栏菜单：用户管理、角色管理、菜单管理、字典管理、代码生成、在线构建器等。
3. 打开浏览器开发者工具的 **Network** 面板，观察每次操作对应的接口请求和 `Authorization` 请求头。
4. 打开 **Vue DevTools**，观察 Pinia 中 `user`、`permission`、`dict`、`tagsView` 等 store 的状态变化。

## 三、重点模块的学习要点

### 1. 工程入口：`src/main.js`

- 注意它的"全局挂载"模式：`app.config.globalProperties` 挂载了 `parseTime`、`resetForm`、`handleTree`、`useDict` 等方法，业务页面可以直接用 `proxy.xxx` 或模板中调用。
- 思考：为什么要把 `DictTag`、`Pagination`、`RightToolbar` 等组件做成全局组件？这样做的收益和代价是什么？

### 2. 请求封装：`src/utils/request.js`

这是整个前端最值得精读的文件之一，包含：

- **请求拦截器**：自动把 Token 放入 `Authorization: Bearer xxx`；GET 参数序列化；对 POST/PUT 做 **防重复提交**（基于 sessionStorage 比较 url、数据和时间间隔）。
- **响应拦截器**：约定后端返回 `{ code, msg, data }` 结构；按 `code` 分别处理 401（会话过期，弹窗提示重新登录）、500、601、非 200 等情况。
- **download 方法**：以 `blob` 方式下载文件，并区分"正常文件"与"后端返回的 JSON 错误信息"。

练习：
- 在请求拦截器里打一条日志，观察哪些请求带了 Token，哪些通过 `headers: { isToken: false }` 跳过了 Token。
- 故意把一个接口的 `code` 改成 500，观察前端提示。

### 3. 路由守卫与动态路由：`src/permission.js` + `src/store/modules/permission.js`

这是理解"若依为什么能根据账号动态生成菜单"的关键：

1. 没有 Token → 除白名单（`/login`、`/register`）外全部跳转到登录页，并带上 `redirect` 参数。
2. 有 Token 但 `roles` 为空 → 调用 `getInfo()` 拉取用户信息和权限，再调用 `generateRoutes()` 请求 `/getRouters` 拿到后端菜单树。
3. `generateRoutes()` 会把后端返回的 `component` 字符串（如 `system/user/index`）通过 `loadView` 映射成真正的组件（基于 `import.meta.glob('./../../views/**/*.vue')`，即 Vite 的批量动态导入）。
4. 通过 `router.addRoute` 注册路由后，用 `{ ...to, replace: true }` 重新导航，确保新路由生效。

思考题：
- 为什么 `permission.js` 里要用 `JSON.parse(JSON.stringify(res.data))` 做三份深拷贝？（提示：`filterAsyncRouter` 会修改原对象。）
- 如果刷新页面，动态路由是怎么重新注册的？（提示：`roles.length === 0` 的判断与 Pinia 状态的生命周期。）
- `constantRoutes` 与 `dynamicRoutes` 有什么区别？（看 `src/router/index.js`。）

### 4. 权限体系：指令、插件与工具函数

- `v-hasPermi="['system:user:add']"`：按钮级权限，没有权限时直接从 DOM 中移除元素。
- `v-hasRole`：按角色控制显示。
- `auth.hasPermi()` / `auth.hasRoleOr()`：在 `<script>` 中用于逻辑判断。
- 约定：权限标识格式为 `模块:子模块:动作`（如 `system:user:edit`），超级管理员拥有 `*:*:*`。

练习：在菜单管理中新建一个菜单，给它设置一个权限标识，再用一个只有部分权限的角色登录，验证按钮是否按预期显示或隐藏。

### 5. 标准 CRUD 页面：以用户管理为模板

打开 `src/views/system/user/index.vue`，按以下结构阅读：

1. **模板区**：搜索表单（`el-form` + `queryParams`）→ 工具栏按钮（带 `v-hasPermi`）→ 数据表格（`el-table`）→ 分页（`Pagination`）→ 弹窗表单（`el-dialog`）。
2. **状态区**：`reactive` / `ref` 定义 `queryParams`、`form`、`rules`、`ids`、`single`、`multiple` 等。
3. **方法区**：`getList`（查询）、`handleQuery` / `resetQuery`、`handleAdd` / `handleUpdate`、`submitForm`、`handleDelete`、`handleExport` 等。
4. **接口区**：对应 `src/api/system/user.js` 中的函数，页面不直接写 URL。

建议：把 `user` 模块的结构照着抄一遍，换成自己的业务实体（比如"图书"），这是最有效的入门练习。

### 6. 字典与公共组件

- `useDict('sys_normal_disable')`：获取字典数据，并在 Pinia 的 `dict` store 中缓存，避免重复请求。
- `<dict-tag :options="..." :value="..."/>`：把字典值渲染成带颜色的标签。
- 对比 `src/utils/dict.js` 与 `src/store/modules/dict.js`，理解缓存的实现位置。

### 7. 代码生成与在线构建器（进阶）

- `src/views/tool/gen/`：导入数据库表 → 编辑字段信息 → 生成代码（前后端）。这部分与后端的代码生成模板配合使用，是理解"元数据驱动开发"的好例子。
- `src/views/tool/build/` + `src/utils/generator/`：可拖拽的表单设计器。`drawingDefault.js` 定义默认组件配置，`html.js` / `js.js` / `css.js` 负责把配置转换成代码字符串，`render.js` 负责在设计器中渲染。
- 这两个模块代码量较大，建议在掌握前 6 个阶段后再读，并且带着"数据结构是什么样的""从配置到代码的转换规则是什么"这两个问题去读。

### 8. 构建与工程化

- `vite.config.js`：`@` 别名指向 `src`；`server.proxy` 配置开发代理；`build.rollupOptions` 控制产物文件名结构。
- `vite/plugins/`：
  - `auto-import.js`：自动导入 Vue / Pinia / Vue Router 的 API，所以很多文件没有写 `import { ref } from 'vue'`。
  - `svg-icon.js`：把 `src/assets/icons/svg` 下的 SVG 打包成雪碧图，通过 `<svg-icon icon-class="...">` 使用。
  - `setup-extend.js`：支持 `<script setup name="...">` 写法（用于 keep-alive 缓存）。
  - `compression.js`：生产构建时生成 gzip 文件。

## 四、动手练习路线（建议按顺序完成）

1. **阅读练习**：不看注释，口头说明一次完整的"登录 → 进入首页"流程，涉及哪些文件、哪些接口。
2. **小改动**：
   - 修改侧边栏 Logo 文字或 `settings.js` 中的标题，观察效果。
   - 修改 `request.js` 中的超时时间，并在慢网络下验证。
3. **新增页面**：在 `src/views/` 下新增一个 `demo/index.vue` 页面，通过后端菜单配置接入，体验动态路由。
4. **仿照实现 CRUD**：以 `system/post`（岗位管理）为模板，独立实现一个"公告分类"或"图书"模块，包括 API 文件、列表页、新增/修改弹窗、删除确认。
5. **权限实践**：为新模块设计三种角色（管理员、编辑、只读），验证按钮和菜单的显示差异。
6. **字典实践**：新增一个字典类型，在页面中用 `useDict` 加载并用 `dict-tag` 展示。
7. **请求层改造**：给响应拦截器增加一个统一的"请求耗时"统计，或者把防重复提交的时间间隔做成可配置项。
8. **构建实践**：执行 `yarn build:prod`，查看 `dist/` 的产物结构，理解为什么要做代码分割（观察 `chunkFileNames` 配置）。
9. **（进阶）**：阅读 `src/utils/generator/` 与 `src/views/tool/build/`，尝试新增一种表单组件（如评分组件），让它能被拖入设计器并生成对应代码。

## 五、常见坑与注意事项

- **页面刷新后菜单丢失或404**：通常是动态路由未注册，检查 `permission.js` 的路由守卫以及后端 `/getRouters` 返回的 `component` 路径是否与 `src/views` 下的文件对应（路径大小写、是否带 `.vue` 后缀都要一致）。
- **接口 404 或 "后端接口连接异常"**：先确认后端是否在 8080 端口启动，再检查 `vite.config.js` 中的 `baseUrl` 与 `.env.development` 中的 `VITE_APP_BASE_API`（默认为 `/dev-api`）。
- **POST 请求被提示"数据正在处理，请勿重复提交"**：这是防重复提交机制触发，间隔默认 1 秒；若确实需要连续提交，可在请求头中设置 `repeatSubmit: false`。
- **按钮有权限却看不到**：检查权限标识拼写是否与数据库菜单中的 `perms` 完全一致（大小写、冒号数量）。
- **修改 `.env` 不生效**：Vite 只在启动时读取环境变量，需要重启 `yarn dev`；并且只有 `VITE_` 前缀的变量会暴露给前端代码。
- **文件编码与换行**：仓库中部分文件是 CRLF 换行，编辑器建议统一配置，避免产生大量无意义的 diff。
- **依赖版本**：`package.json` 中固定了较多版本，并通过 `overrides` / `resolutions` 锁定了 `quill`。升级依赖前先阅读对应库的迁移指南，尤其是 Element Plus 和 Vite。
